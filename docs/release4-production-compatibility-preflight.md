## Customer, Driver and Admin risk

The code-path check found no immediate missing-schema call with both flags OFF. Customer quote/booking introduces server quote-version checking; the current Customer UI supplies the expected version, but this changes API behavior for other clients and removes a previous local fare-display fallback. Driver Earnings mounts the dormant payout panel and should show `available:false` without new tables. Admin Online Payouts similarly shows the disabled state; dashboard, payment reviews, trips, Finance and Settlements still use existing tables. The Admin dashboard changed from a count-only payment-review summary to retrieving and decorating the full request list; production currently has 31 requests, so the current dataset is below PostgREST's common page limit, but this is a performance and future-count risk.

The major no-regression blocker is source divergence. `git merge-base` of this candidate and local performance commit `606c8106c074866c3380348d520e5c2aaf5b0aa0` is older `a7f5b9b880cbc47e7ef42e91c62eb5133116a2d9`. Compared with that newer local source, this candidate removes the bounded/retryable Driver profile load and its retry control, reverts parallel Driver dashboard reads to sequential reads, restores continuous 1-second ticking and more frequent surge fetches, and reverts Customer active-trip recovery/loading handling. It also removes the performance telemetry files (the public intake was already disabled in the newer source). These are material Customer/Driver behavior and reliability differences unrelated to the two dormant financial flags. The current Vercel artifact is newer than the supplied rollback artifact, but its available metadata does not establish that it equals `606c8106` or any other Git commit. Successful local Release 4 tests cannot certify equivalence to an unidentified live artifact.

## Release and recovery decision

**BLOCKED — Required evidence is unavailable.** The production database itself does not require the four Release 4 candidates to serve the payout/fare-OFF application, but deploying this branch as-is cannot be certified to preserve the currently serving Customer and Driver behavior. The smallest safe next action is to establish a reviewed source baseline for `dpl_Ei4EnnbPGGgaWdKAojC9NJjydFg7` (or an independently matched artifact inventory), then carry the Release 4 changes onto that baseline while retaining the newer reliability changes, and run focused Customer/Driver/Admin regression plus a production-target unaliased smoke check. If exact old-source equivalence remains unavailable, explicitly review the complete replacement diff against the best supported source and accept that provenance limit; do not claim SHA parity. Recheck effective Production flag values, current domains and rollback deployment at that later gate.

The previous 359/359 tests, TypeScript, zero-error lint and 215/215-page local build support the unchanged application source, but no authenticated production workflow or live-provider test was performed in this preflight. Actual Yoco fee evidence, bank matching, consent/accounting and payout activation remain separate later gates. No deployment, migration or activation is authorized by this report.
